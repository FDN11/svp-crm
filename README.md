# СВП CRM

Лёгкая CRM для набора дилерской сети СВП: лиды из парсинга → воронка → сделки с товарами.
Один процесс Node, SQLite-файл, никаких внешних сервисов. Стилистика — как у сайта (графит, оранжевый, Jost).

## Запуск

```bash
npm install
npm start            # http://localhost:3000
```

Нужен Node ≥ 22.5 (встроенный `node:sqlite`). База создаётся сама в `data/crm.db`.

Загрузка данных:

```bash
# лиды из парсинга (формат — см. leads/leads-pilot.json в основном проекте)
npm run import:leads -- ../leads/leads-pilot.json

# дилерский прайс с сайта → справочник товаров
npm run import:products -- ../site/src/data/price-list.json

# то же в облачную CRM (адрес и логин:пароль третьим и четвёртым аргументом)
npm run import:leads -- ../leads/leads-pilot.json https://svp-crm-production.up.railway.app svp:ПАРОЛЬ
```

Повторный импорт лидов безопасен: дубли по `id` из парсинга пропускаются.

## Что умеет

**Лиды** — канбан по этапам `Новый → В работе → Контакт установлен → Квалифицирован`.
Карточки тянутся мышью между колонками. В карточке: телефоны (кликабельные), сайт, точки продаж, приоритет,
конкурент на полке, следующее действие и дата, лента комментариев и событий.

Исход лида — одна из кнопок:
- **В сделку** — создаёт сделку, лид закрывается как `won` и ссылается на неё;
- **Догрев / Не квал / Отказ** — лид уходит с доски на «полку» под ней, откуда его можно вернуть.

**Сделки** — канбан `Новая → КП отправлено → Согласование → Счёт выставлен → Оплачена → Отгружена`,
исход `Выиграна / Проиграна`. В сделке: позиции из справочника товаров (кол-во, дилерская цена, итог считается сам),
НДС, ИНН, контакт, следующее действие, лента.

**Товары** — справочник из дилерского прайса (47 позиций), для подбора в сделку.

Поиск в шапке ищет по компании, городу и телефону; фильтры по городу и сегменту — на доске лидов.

## Устройство

```
server.js        Express, REST API, раздача public/
db.js            схема SQLite, этапы воронок, утилиты
public/          интерфейс: index.html, styles.css, app.js — без сборки
scripts/         импорт лидов и товаров
data/crm.db      база (в .gitignore)
```

Этапы воронок описаны одним массивом в `db.js` — переименовать или добавить колонку = поправить его.

### API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/leads?q=&city=&segment=&outcome=active` | список лидов |
| POST | `/api/leads` · `/api/leads/import` | новый лид · пачка из парсинга |
| PATCH | `/api/leads/:id` | поля, `stage`, `outcome` |
| POST | `/api/leads/:id/convert` | лид → сделка |
| GET/POST/PATCH | `/api/deals`, `/api/deals/:id` | сделки |
| POST/PATCH/DELETE | `/api/deals/:id/items[/:itemId]` | позиции сделки |
| POST | `/api/leads/:id/activities`, `/api/deals/:id/activities` | комментарий в ленту |
| GET | `/api/products`, `/api/stats`, `/api/meta` | справочники и сводка |
| POST | `/api/products/import` | обновить справочник из прайса |
| POST | `/api/webhooks/:source` | входящие события извне |

## Интеграции (задел)

Единая лента `activities` хранит и комментарии менеджера, и внешние события — звонки, письма, сообщения.
Точка входа для них уже есть: `POST /api/webhooks/<source>` с телом `{ phone, kind, text, ... }`
находит лида по номеру телефона и пишет событие в его ленту.

```bash
curl -X POST localhost:3000/api/webhooks/telephony \
  -H 'Content-Type: application/json' \
  -d '{"phone":"+7 (343) 318-24-91","kind":"call","text":"Входящий, 3 мин"}'
```

Куда подключать дальше:
- **Телефония** (Mango, UIS, Zadarma, Sipuni) — их webhook на события звонка → `/api/webhooks/telephony`; click-to-call вместо `tel:` в карточке.
- **Почта** — IMAP-поллер или webhook почтового сервиса, матчинг по `email` лида/сделки → `/api/webhooks/mail`.
- **Мессенджеры** (Telegram Bot API, WhatsApp Business, MAX) — бот пишет входящие в `/api/webhooks/telegram` и т.п.; для исходящих — эндпоинт `POST /api/leads/:id/send` поверх того же провайдера.
- **Парсинг** — новые прогоны шлют результат в `/api/leads/import`, дубли отсекаются по `ext_id`.

## Деплой

Подходит любой VPS с Node. Пример под `systemd`/`pm2`:

```bash
PORT=3000 CRM_DB=/var/lib/svp-crm/crm.db node server.js
```

Доступ для команды — общий логин/пароль через переменные `CRM_USER` и `CRM_PASS`
(без них сервер открыт — режим локальной разработки).

**Railway** (готовый `railway.json`): создать сервис из этого репозитория, подключить Volume в `/data`,
задать переменные `CRM_DB=/data/crm.db`, `CRM_USER`, `CRM_PASS` и открыть публичный домен.
Бэкап — копия файла `crm.db` (база в режиме WAL, копировать через `sqlite3 crm.db ".backup copy.db"`).
